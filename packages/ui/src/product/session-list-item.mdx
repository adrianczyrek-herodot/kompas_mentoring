# SessionListItem

## 1. Do czego służy

Jeden wiersz listy sesji: kiedy, z kim, z jakim celem i w jakim statusie — żeby uczeń (U4) i mentor
(M2) w kilka sekund przejrzeli wiele sesji i weszli w szczegóły jednej (U5).

<Canvas of={SessionListItemStories.Playground} />
<Controls of={SessionListItemStories.Playground} />

## 2. Kiedy używać

| Sytuacja w Kompasie | Źródło |
|---|---|
| Lista „Nadchodzące” i „Minione” w Moich sesjach (U4), pod kartą najbliższej sesji | KONCEPCJA §U4, E3-S5 |
| Historia sesji z jednym uczniem lub mentorem (M4, filtr po mentorze w U4) | KONCEPCJA §U4, §M4 |
| Każda gęsta lista rezerwacji, w której wiersz prowadzi do U5 | R01.1, R01.4, K1 |

## 3. Kiedy nie używać

| Zamiast wiersza | Użyj | Źródło |
|---|---|---|
| Najbliższa sesja z „Dołącz” na górze U4 | `NextSessionCard` | KONCEPCJA §U4, R01.6 |
| Dzisiejsze sesje mentora z „Dołącz” w M2 | `TodayAgenda` | KONCEPCJA §M2 |
| Prośba o sesję próbną z decyzją mentora | `TrialRequestCard` | E3-S7 |
| Pojedyncza sesja w nagłówku szczegółów (U5) | `PageHeader` + `BookingStatusBadge` | KONCEPCJA §U5 |
| Wiersz jako karta z cieniem w siatce | wiersze w `ul`, oddzielone linią | R01.4 |

## 4. Anatomia

| Część | Wymagana | Opis | Źródło |
|---|---|---|---|
| Dzień i godzina | tak | `DateTime` `weekday` + `time` · czas trwania; pierwsza kolumna, cyfry tabelaryczne | R01.1, R01.3, brief reguła 10 |
| Awatar | tak | inicjały `withName` (`Avatar` `sm`), dekoracyjny obok imienia | — |
| Imię i nazwisko | tak | `Link` do U5 (`href`) — jedyny element nawigujący wiersza | KONCEPCJA §U4, §U5 |
| Typ sesji | tak | „Sesja próbna” albo „Plan” po imieniu | KONCEPCJA §U4 |
| Cel | tak | `goal`, najwyżej 2 linie (`line-clamp-2`) | KONCEPCJA §U2 („Z czym przychodzisz?”) |
| Status | tak | `BookingStatusBadge` — ikona i słowo | WCAG 1.4.1 |
| Szybka akcja | nie | slot `action`, np. „Przełóż”, zawsze drugorzędna | KONCEPCJA §U4, R01.6 |
| Linia podziału | tak | `border-border-divider` pod wierszem, bez cienia | R01.4 |

## 5. Warianty

Komponent nie ma propu wariantu. Różnice wynikają z danych: `type` (`trial` / `plan`), `status`
(7 wartości, sekcja 6) i obecności `action`.

<Canvas of={SessionListItemStories.Statuses} />

| Dane | Wynik | Źródło |
|---|---|---|
| `type: 'trial'` | dopisek „Sesja próbna”, zwykle `durationMin: 30` | KONCEPCJA §U4 |
| `type: 'plan'` | dopisek „Plan” | KONCEPCJA §U4 |
| `action` podany | przycisk drugorzędny obok statusu | KONCEPCJA §U4 (szybkie akcje), R01.6 |

## 7. Zachowanie i dostępność

| Zasada | Źródło |
|---|---|
| Renderuje `li` — zawsze w `ul` z `aria-label` (np. „Sesje”); czytnik ogłasza „lista, N elementów”. | WCAG 1.3.1 |
| Fokus: link z imieniem, potem `action`; kolejność = DOM = kolejność wizualna. | WCAG 2.4.3 |
| Link ma nazwę = imię i nazwisko; czytnik czyta: dzień, godzina, czas trwania, „link Ewa Sadowska”, typ, cel, status słowem. | WCAG 2.4.4, 4.1.2 |
| Data w `time datetime` (ISO), widoczny tekst w strefie oglądającego. | brief reguła 10 |
| Status zawsze słowem; ikona `aria-hidden`. | WCAG 1.4.1 |
| Cel kliknięcia linku i akcji ≥ 24 × 24 px (WCAG), w Kompasie 44 px — przycisk `sm` ma pole 44 px. | WCAG 2.5.8, K1, Z6 |
| Szkielet ma `aria-hidden`, stan ogłasza lista przez `aria-busy` i etykietę. | WAI-ARIA 1.2 (`aria-busy`) |

## 10. API

| Prop | Typ | Domyślnie | Opis |
|---|---|---|---|
| `session` | `SessionSummary` | — | `id`, `startsAt` (ISO), `durationMin` (`30 \| 60`), `type` (`'trial' \| 'plan'`), `status` (`BookingStatus`), `withName`, `goal` |
| `timeZone` | `string` (IANA) | — | strefa oglądającego, np. `Europe/Warsaw` |
| `href` | `string` | — | adres U5 (`/sesje/:id`) |
| `linkRender` | `ReactElement` | — | element linku z routera (np. `next/link`), przekazany do `Link` |
| `action` | `ReactNode` | — | szybka akcja drugorzędna |
| `className` | `string` | — | tylko układ |
| pozostałe | atrybuty `li` | — | `aria-*`, `data-*` |

`SessionListItemSkeleton` — wiersz szkieletu, bez propów.

## 11. Kod

```tsx
import { SessionListItem } from '@kompas/ui';

<ul aria-label="Sesje">
  <SessionListItem session={session} timeZone={viewerTimeZone} href={`/sesje/${session.id}`} />
</ul>
```

Typowy przykład z produktu (U4, zakładka „Nadchodzące”):

```tsx
import { Button, EmptyState, ErrorState, SessionListItem, SessionListItemSkeleton } from '@kompas/ui';
import NextLink from 'next/link';

{status === 'loading' ? (
  <ul aria-busy="true" aria-label={t('sessionsLoading')}>
    <SessionListItemSkeleton />
    <SessionListItemSkeleton />
    <SessionListItemSkeleton />
  </ul>
) : status === 'error' ? (
  <ErrorState titleAs="p" title={t('sessionsError')} action={<Button variant="outline" onClick={retry}>{t('retry')}</Button>} />
) : sessions.length === 0 ? (
  <EmptyState titleAs="p" title={t('sessionsEmpty')} action={<Button>{t('findMentor')}</Button>} />
) : (
  <ul aria-label={t('sessionsUpcoming')}>
    {sessions.map((session) => (
      <SessionListItem
        key={session.id}
        session={session}
        timeZone={viewerTimeZone}
        href={`/sesje/${session.id}`}
        linkRender={<NextLink href={`/sesje/${session.id}`} />}
        action={<Button variant="outline" size="sm">{t('reschedule')}</Button>}
      />
    ))}
  </ul>
)}
```

## 13. Powiązane

- **Składa się z:** `DateTime`, `Avatar`, `Link`, `BookingStatusBadge`, `Skeleton`.
- **Mylony z:** `NextSessionCard` (jedna sesja z akcją główną), `TodayAgenda` (dzień mentora z „Dołącz”), `TrialRequestCard` (decyzja mentora).
- **Wzorce:** lista z filtrami (U4: zakładki `Tabs` Nadchodzące / Minione, filtr po mentorze), stany danych listy (`EmptyState`, `ErrorState`), widok szczegółów (U5).
